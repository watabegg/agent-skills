# H1: Serializable MVCC store
Difficulty: hard

Implement mvcc.py with Store, Transaction, ConflictError(Exception). This is an IN-MEMORY, SINGLE-THREADED model of optimistic serializable transactions, with historical reads, phantom detection, and savepoints; no SQL/database dependency.
Store(): empty, integer version property initially 0. Store.begin() -> Transaction whose snapshot is the store's current version. Store.read(key, version=None) -> deep copy of value at that committed version, or None if absent. Values are non-None JSON-compatible values; keys are strings (including empty). Explicit version must be an int excluding bool, 0<=v<=current version; else ValueError. version=None means current. Store.scan(start=None,end=None,version=None) -> list[(key,deep-copied value)] of PRESENT keys in lexicographic order, half-open string range start<=key<end; None unbounded; start>=end gives empty. Same version validation. All other input types valid as specified. Values can contain mutable nested structures. All historical versions remain queryable.
Transaction.snapshot is its captured integer version. get(key) -> own staged value if present, else snapshot value, deep copied; absent -> None. put(key,value) stages a deep copy; delete(key) stages absence, both return None. scan(start=None,end=None) merges snapshot with own staged writes/deletes and returns ordered fresh pairs. Read-your-writes always applies, including after savepoint rollback.
For serializability, every get records a point-read obligation EVEN if it is satisfied by a staged write; every scan records its entire requested half-open range EVEN if it returns empty (empty/inverted ranges contain no keys). put/delete record write intentions without implicit read obligations. At commit: conflict if ANY key in current final write set OR any point-read key OR any key in a recorded range has a committed write at a version greater than this transaction's snapshot. Every successful nonempty-write transaction counts as a committed write to every staged key, including setting an equal value, deleting an absent key, and ABA changes. This is intentionally conservative, and detects phantoms even if a later deletion hides an insertion. Validate against write HISTORY, not only final visible values. ConflictError closes the transaction and applies no writes/version increment. Disjoint writers may both commit. Read-only commits must validate read obligations too.
commit() -> store version after success. If final write set nonempty, apply all keys atomically under one NEW version (current+1); otherwise do not increment. Close transaction on success or conflict. rollback() -> None, closes transaction with no commit. Any Transaction operation below or above after close, except reading snapshot, raises RuntimeError. Conflicting commit followed by further operations raises RuntimeError.
savepoint(name) -> None: create named savepoint of current staged writes. Existing name -> ValueError with no change. rollback_to(name) -> None: restore writes as at that savepoint, retain that named savepoint, discard savepoints created AFTER it. READ OBLIGATIONS ARE STICKY: do NOT undo get/scan obligations. Missing name -> ValueError no change. release(name) -> None: remove that savepoint and all created after it, KEEP current staged writes and all read obligations; missing -> ValueError. Names strings. Reusing discarded/released names allowed. State snapshots must not alias later writes or caller data. Savepoints have no effect on committed store history.
No retention/GC or actual multithreading needed. Scale: 200 keys, 1000 committed versions, 100 open transactions. Direct scan over changed keys/history is acceptable, but avoid copying the whole store on every begin. Store reads and scans cannot leak mutable internals. Exact exported class and method names as above. Standard library only.
