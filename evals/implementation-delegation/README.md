# 実装委譲の公開評価アーカイブ

## 概要と目的

本ディレクトリ（`evals/implementation-delegation/`）は、将来的に低コストな実装委譲を進める際の参考資料として、過去の調査記録と検証課題をまとめた公開アーカイブです。モデル間の優劣を競う順位表の作成や、特定モデルの優位性を主張することを目的としたものではありません。

本アーカイブの公開にあたっては、非公開の組織名や製品名、ファイルパス、実行ログ、対話セッション識別子、外部URL、ならびに元となった非公開課題の固有情報はすべて除外しています。過去に実施された5つの調査シリーズは全件保存していますが、再利用可能な課題としてパッケージ化して提供するのは3件に絞っています。実際の修正前リポジトリを対象とした調査結果は、集約された匿名データとしてのみ掲載しており、本番環境の課題やソースコードそのものは公開していません。また、汎用的な代替課題の作成は将来の任意作業として位置づけており、現時点では追加していません。

本アーカイブはリポジトリの最上位にある README からリンクされていますが、`luna-impl` などの実装本体は本アーカイブへの依存関係を持ちません。スキルのコード、標準設定、プロンプトも変更していません。なお、公開されているテストケースは世界的に秘匿されたものではないため、モデルの学習データや将来の評価者に露出する可能性があります。また、本アーカイブの整理にあたって、新たなモデルのベンチマーク測定は実施していません。

## 選択された再利用可能課題

過去の調査から選定し、再利用可能な形で収録した課題は以下の3件です。難易度は作成者の見積もりです。

| 課題へのリンク | 主な仕様と検証内容 | 推定難易度 |
| :--- | :--- | :--- |
| [tasks/lease-queue/](tasks/lease-queue/) | 状態遷移、リース期限切れ、再試行制御、厳密なAPI仕様の遵守。元の復元状態は `task.json` に記録。 | 作成者見積もり |
| [tasks/build-graph/](tasks/build-graph/) | 依存関係の伝播と無効化処理の実装。 | 中（作成者見積もり） |
| [tasks/mvcc/](tasks/mvcc/) | 直列化可能トランザクション、競合検出、セーブポイント、ロールバックの制御。 | 難（作成者見積もり） |

課題パッケージの実装は完了しており、`task.json` に含まれる3件はすべて実行可能です。保存されている合格済みの提出物を用いた確認では、build-graph と mvcc はそれぞれ評価器チェック20件と公開チェック1件に合格しています。lease-queue では復元候補が43件中42件、単一のハートビート戻り値を調整した版が43件中43件に合格しており、公開チェックはいずれも5件に合格しています。ただし、これらはオフラインでのパッケージング検証であり、新たなモデル試行や当時の実行環境の完全な再現を意味するものではありません。各課題のバージョン、ハッシュ値、実行コマンドは `task.json` に、復元に関する注記は各 README に記載されています。今後のモデル評価や比較検証を行う際は、公平性を保つため、比較する条件間で同一バージョンの課題を使用してください。

各課題の実行手順は個別に記載されています。本アーカイブの実行環境自体にはアクセス制御を強制する仕組みはないため、運用担当者が手順に沿って環境を隔離し、解答側のモデルには仕様書、初期コード、公開テストのみを提供して、評価器や過去の実行結果、履歴情報などを渡さないように運用する必要があります。

## 調査シリーズの索引

過去に実施した5つの調査シリーズの概要と各 README へのリンクは以下のとおりです。

- [studies/workflow-dag/README.md](studies/workflow-dag/README.md)
  2026年8月実施。初期の3条件すべてで13件中13件のテストに合格しました。生成された本番コード行数はそれぞれ241行、113行、127行でした。本調査は解答側のモデルがファイルシステム経由で評価器にアクセスできる環境で実施されており、完全なブラインド評価ではありません。所要時間とコストは不明です。なお、コード行数の多寡は品質スコアを示すものではありません。

- [studies/lease-queue/README.md](studies/lease-queue/README.md)
  2026年8月実施。曖昧な指示を与えた Luna では43件中24件、明確な指示を与えた Luna では43件中43件、元のスキル構成では43件中43件、改定版スキルでは43件中42件のテストに合格しました。改定版で43件中42件の合格となったのは、改定版の指示文で生存確認成功時の戻り値の仕様が抜けていたためであり、状態遷移自体は正常だったものの実装が None を返したのに対し評価器が Lease を期待したという仕様の不一致によるものです。提示された指示文が同一ではないため、この1件の差をもってスキルの性能劣化と結論づけることはできません。実行構成としては、親エージェントに Sol/high、作業ワーカーに当初5体、のちに2体の Luna/max を配置し、凝集度の高い実装担当者と独立したテスト担当者を分けるワークフローを採用しました。所要時間は36分33秒から16分36秒に短縮し、当時のAPI換算コストの見積もりは1.586米ドルから1.759米ドルへと変化したことが計測されましたが、試行回数は1回のみであり因果関係を証明するものではありません。なお、本調査で使用したモデルはすべて当時の旧版 GPT-5.6 です。

- [studies/migration-pilot/README.md](studies/migration-pilot/README.md)
  2026年9月実施。1つのモジュールと3つの関数を対象に、4条件で各2回の試行を行ったところ、全試行で283件中283件のテストに合格しました。これはツールを使わない単体コード生成の評価であり、スキル全体の機能を検証したものではありません。テスト結果は満点で飽和しており、当時の要求モデルのみが記録されています。

- [studies/synthetic-subagents/README.md](studies/synthetic-subagents/README.md)
  2026年9月実施。4つの独自課題と計12件の提出物を対象に、Astra/low を評価器として採点しました。正解性80点、保守性10点、テスト品質10点の計100点満点で評価しています。平均得点は新 Luna/max が97.25点、新 Luna/high が95.75点、旧 Luna/max が97.75点で、平均所要時間はそれぞれ452.5秒、279.2秒、446.3秒でした。新 Luna/max ではモデルの処理自体は完了したものの、実行時間を検証する性能テストケースで1件の不合格（基準3.5秒に対し計測値3.664秒）が発生しました。なお、確定した評価スコアと補足の再実行記録は別枠で分離して保管されています。条件あたり1回の試行に基づく結果であり、モデルの一般的な序列を示すものではありません。なお、このシリーズから再利用可能課題として提供しているのは build-graph と mvcc の2件のみです。

- [studies/repository-replay/README.md](studies/repository-replay/README.md)
  2026年9月実施。実際の非公開な修正前リポジトリを用いた2つのユースケースに対し、新 Luna/high、max、xhigh を適用しました（公開されている調査結果は匿名化されています）。有効な主要6条件のすべてでテストに合格（9件中9件、または15件中15件）し、所要時間は high が最速でした。一方でユースケースAの定性評価では、high の保守性が6点、テスト品質が4点にとどまったのに対し、max と xhigh はいずれも保守性8点、テスト品質7点を記録しました。テストに合格したことと、成果物の品質が同等であることは一致しない実態を示しています。なお、主要条件Bは無効なセットアップのあとに再実行されており、ユースケースAでは提出後に評価器アダプターを修正した経緯も記録されています。実験全体で把握されているAPI換算コストの見積もりはワーカー約1.59米ドル、親約98.44米ドルですが、外部の最上位処理や監査、末尾処理は除外されています。これらは実際の請求額ではなく、監視カテゴリもすべてがポーリングというわけではありません。元のリポジトリを特定できるソースコードの詳細は一切含まれていません。

## 記録データの構成と解釈基準

各調査ディレクトリには、調査のメタデータを保持する `manifest.json` と、実行結果を記録した `results.jsonl` が配置されています。データの参照と解釈にあたっては、以下の基準に従ってください。

- **証拠の有無とモデルの区別**: 証拠データが存在しない項目には `null` を記録しています。また、実行時に要求したモデル名（requested）と実際に観測されたモデル名（observed）は分けて管理しています。
- **指標の独立性**: 証拠レベル（`evidence_level`）と公開環境での再現性（`public_reproducibility`）は独立した指標として扱っています。客観的なテスト結果、主観的な評価スコア、実行時チェックの結果は明確に区別し、性質の異なるチェック件数を合算してはなりません。
- **コスト集計範囲の分離**: コストは親、セットアップ、評価、ワーカーの各範囲に分けて集計しています。記載されているレートは当時の見積もり値であり、現行の価格体系や実際の請求額を示すものではありません。
- **実行記録の保持**: 失敗した記録、無効となった記録、探索的な記録も除外せずに保存しています。元の対話セッションの生データや非公開の来歴情報はリポジトリ外に保管されています。

リポジトリの最上位ディレクトリから以下のコマンドを実行することで、記録ファイル、マニフェスト、成果物ハッシュの整合性を検証できます。

```sh
python3 evals/implementation-delegation/scripts/validate_records.py
```

このコマンドはメタデータやハッシュ値の整合性を機械的に確認するためのものであり、モデルの実装能力を測定・検証するものではありません。
