## accepted-risk rule

次を満たさない accepted risk は無効とする。

- exact risk ID と finding/evidence
- affected SHA、task、scope
- release effect
- compensating control
- expiry または reconsider condition
- authority と decision ref

correctness、durability、identity、release evidence の critical risk を、時間だけを理由に自動 accepted-risk へ変えない。

## risk review cadence

- task start 前: affected risk を contract へ添付
- batch close: likelihood/early signal を更新
- broad epoch collection 後: new risk ではなく finding ledger と対応付け
- remediation 後: control の regression evidence を追加
- release 前: critical/high risk が open でないことを確認
- retrospective: recurrence と control effectiveness を memory candidate にする

## closure evidence

risk は test が1件通っただけでは close しない。次を必要とする。

- preventive control の実装 SHA
- trigger regression
- adjacent positive regression
- operator recovery path
- exact-SHA integration evidence
- risk owner の確認

外部 decision が必要な RR-18 は、コード側の fail-closed が通っていても `open-external` として残す。
