# herdr-dev-loop 0.5.3 closeout acceptance matrix

Status: proposed verification ledger

## 使い方

この matrix は、0.5.3 の「実装したつもり」を防ぎ、受入条件、既知 finding、test、release evidence を exact SHA で結び付ける。

状態は次の5値だけを使う。

- `inherited`: HEAD `043eb92` で実装済みと監査されたが、final SHA で再検証が必要
- `candidate`: T050/T051 候補に実装があるが未統合または review 未合格
- `planned-fix`: closeout task で修正する
- `external-decision`: repository code だけでは確定できない
- `passed`: final exact SHA の evidence が揃った

この文書作成時点で `passed` は付けない。

## validation evidence catalog

各 evidence record は次を持つ。

- exact target SHA
- ordered command argv
- working directory
- environment identity
- dependency identity
- start/end timestamp
- exit status
- stdout/stderr artifact digest
- test count または scenario count
- changed source identity
- reusable/stale classification

### L1 task evidence

- focused unit tests
- schema parity tests
- negative/replay/concurrency/fault-injection tests
- task diff self-review
- `git diff --check`

### L2 integration evidence

- adjacent module suites
- candidate import union check
- migration/schema wrapper parity
- task-to-task invariant tests
- exact candidate Patch Review

### L3 release evidence

- full discovery
- selftest
- skill quick validation
- exact-SHA 21-scenario synthetic
- fail-closed and migration crash matrix
- Reviewer/Gap epoch completeness
- independent manual-final
- Codex/Claude install parity
- companion capability handshake

同じ SHA と同じ command/dependency identity の L3 evidence は再利用できる。source、command、environment、dependency のどれかが変われば stale にする。

## final closure rule

finding は次の全条件でのみ `resolved` になる。

1. fix commit と exact SHA がある。
2. finding の trigger を再現する negative test が、修正後は期待どおり拒否または成功する。
3. adjacent invariant の positive regression が通る。
4. Reviewer closure lane が source finding を確認する。
5. mandatory regression challenge が新しい blocking regression を見つけない。
6. acceptance condition と release evidence の link がある。

単に fingerprint が次の review に現れなかっただけでは resolved としない。

## release blocking conditions

- matrix に `planned-fix` が残る。
- `external-decision` の release-required identity が未確定である。
- final SHA と evidence SHA が違う。
- full suite または synthetic が一部しか実行されていない。
- Reviewer/Gap lane または verifier が missing である。
- review/remediation budget を requeue で回避している。
- accepted-risk に user authority と exact scope がない。
- unrelated finding を in-scope fix として混ぜた。
