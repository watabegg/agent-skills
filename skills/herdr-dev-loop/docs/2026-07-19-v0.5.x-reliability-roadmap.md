# herdr-dev-loop 0.5.x reliability roadmap

Status: roadmap proposal

## 方向性

0.5.x では、機能を広げる前に自己ホスト開発の収束性を上げる。優先順は次である。

1. 0.5.3 を元の受入条件どおり完了させる。
2. 0.5.4 で Manager continuity と repository memory を製品化する。
3. 0.5.5 で中央 CLI と transaction boundary を分割する。
4. 0.5.6 で review/validation evidence の再利用と性能計測を仕上げる。

version は 0.5.x を維持する。新しい major/minor family を増やさず、小さい release ごとに一つの構造問題を閉じる。

## 0.5.3: bounded review convergence completion

### 主目的

承認済み 0.5.3 計画の未達を閉じ、exact-SHA release evidence を作る。

### 必須

- immutable planning identity と coverage Scout
- task risk、candidate、Patch Review、full-suite gates
- Reviewer/Gap coordinated swarms
- common remediation ledger
- task-lifetime Patch Review cap と single-use extra round
- broker-native ACK approval acquisition
- review epoch lineage、quarantine、successor recovery
- collision-free Git probe
- authenticated independent final
- accurate enough pause/requeue/ACK outcome metrics
- copied-skill and companion release harness
- install parity and capability handshake

### 非目標

- repository-wide memory database
- hloop CLI の全面分割
- successor task lineage を跨ぐ汎用 budget
- general-purpose pane transport replacement
- unlimited review convergence

### release gate

[0.5.3 closeout plan](2026-07-19-v0.5.3-closeout-plan.md) と [acceptance matrix](2026-07-19-v0.5.3-closeout-acceptance-matrix.md) に従う。

## 0.5.4: Manager continuity and repository memory

### 主目的

「作業が進むにつれて skill が使えなくなる」状態を、session の注意力ではなく durable projection と enforced guard で防ぐ。

### 0.5.4-A: identity and incident store

- Git common-dir repository UUID
- XDG state root
- SQLite WAL event ledger
- Manager-only writer
- privacy serializer
- candidate/verified/refuted/stale/resolved state
- backup/restore/migration

### 0.5.4-B: deterministic brief and handoff

- Manager brief
- Manager lease and rotation
- batch-boundary handoff capsule
- next-safe-action projection
- exact source digest and staleness
- weighted progress projection

### 0.5.4-C: repeated-failure circuit

- failure class taxonomy
- threshold and dispatch freeze
- recovery action and evidence
- force override with decision ref
- runtime drift and worktree ownership guards

### 0.5.4-D: role projections and promotion

- task-relevant Worker guardrails
- Reviewer closure/challenge split
- token budget
- near-duplicate proposals
- user-gated committed lesson promotion

### 受入条件の中心

- fresh Manager が old conversation なしに安全な next action を再現できる。
- memory が scope を増やさない。
- 同じ operational failure の3回目を機械的に止める。
- raw input/credential を保存しない。
- worktree/rename/run archive を跨いで repository identity を維持する。

詳細は [repository memory design](2026-07-19-v0.5.4-repository-memory-design.md) を参照する。

## 0.5.5: modular runtime and transaction boundaries

### 問題

中央 `scripts/hloop` は 0.5.3 integration HEAD で約35,797行、T051 candidate で約37,372行に達した。planning、ACK、review、remediation、certification、Git、CLI dispatch が同じ file に集中し、task を安全に並列化しにくい。局所修正が隣接 lifecycle の regression を作りやすい。

### 主目的

機能境界と transaction boundary を一致させ、task 分解と review surface を小さくする。同時に、native manual-finalを完成させ、`codex-review-multi-v2`をHLoop publicationの必須依存から明示選択時だけのoptional companionへ移す。

### module proposal

```text
scripts/hloop_cli/
├── parser.py
├── manager.py
├── worker.py
├── review.py
├── gap.py
├── ack.py
├── lifecycle.py
├── recovery.py
└── completion.py

scripts/hloop_lib/
├── state_store.py
├── transaction.py
├── identity.py
├── semantic_ack.py
├── task_lifetime.py
├── review_epoch.py
├── remediation.py
├── certification.py
├── git_safety.py
└── memory.py
```

top-level `hloop` は parser bootstrap と command registry に限定する。

### migration rule

- behavior-preserving extraction を先に行う。
- extraction と feature change を同じ task に入れない。
- command argv、stdout/stderr、exit code、schema を golden test で固定する。
- state mutation は transaction API 以外から行えないようにする。
- ownership map を作り、cleanup が他 role の worktree を削除できないようにする。

### release slices

1. 0.5.5-A: parser/command registry extraction
2. 0.5.5-B: state transaction and lifecycle extraction
3. 0.5.5-C: ACK/review/remediation extraction
4. 0.5.5-D: Git/recovery/certification extraction
5. 0.5.5-E: native manual-final and optional companion boundary

各 slice は full compatibility suite と migration rollback を持つ。

protocol依存解消の詳細、互換性、検証matrix、rolloutは[native manual-final と companion 任意化計画](2026-07-22-v0.5.5-native-manual-final-plan.md)に固定する。module抽出と挙動変更は同じcommitへ混ぜず、nativeとexternalを同じcanonical certification gateへ正規化する。

## 0.5.6: evidence economy and measurable convergence

### 主目的

品質 gate を維持しながら、同じ exact SHA での重複 test、重複 review、待機操作を減らす。

### features

- exact-SHA validation catalog and cache
- command/dependency/environment identity
- code-sensitive/non-code-sensitive staleness
- Reviewer/Gap evidence reuse
- collection burst coalescing
- review epoch saturation metrics
- attempt-level runtime intervals
- Manager sleep/user decision/ACK phase metrics
- pause-clamped wall/active/wait definitions
- cost、agent time、wall time、quality を別指標で記録

### convergence metrics

- first discovery coverage ratio
- finding escape rate after round 1/2
- regression challenge hit rate
- exact SHA あたり full-suite count
- task lifetime Patch Review rounds
- requeue count and cause
- TUI message count per task
- Manager attention interruptions
- unresolved finding retention at stop

数字を改善するために finding を抑制しない。測定定義と raw intervals を outcome artifact へ残す。

## 0.5.7 candidates

0.5.4 から 0.5.6 の実測後に判断する候補である。

- successor task lineage を跨ぐ fix budget
- provider-neutral non-TUI role runner
- distributed Manager lease
- cross-repository verified lesson catalog
- adaptive model selection based on task risk and regression history
- automated task split proposal from write-scope and invariant graph

現時点では計画へ固定しない。前 release の evidence なしに scope を予約しないためである。

## model policy proposal

model 名だけで品質を保証しないが、risk と役割に応じて下限を設ける。

| risk/role | proposed default | 理由 |
| --- | --- | --- |
| low-risk isolated Worker | `gpt-5.6-terra` max | 狭い変更と明確な tests |
| medium/high-risk Worker | `gpt-5.6-sol` xhigh | central state、migration、identity、concurrency |
| Patch Reviewer | `gpt-5.6-sol` xhigh | candidate-local adversarial review |
| Reviewer/Gap Coordinator | `gpt-5.6-sol` xhigh | coverage plan と統合 judgment |
| Reviewer/Gap lane/verifier | `gpt-5.6-sol` xhigh | independent deep audit |
| Advisor | `gpt-5.6-luna` max | 相談と選択肢整理。gate 代替なし |

Worker の品質改善は model だけに任せない。task contract に Repository Impact Map、preserved invariant、negative regression、adjacent consumer を含め、submit 前の self-review matrix を要求する。

## release sequencing rules

1. 一つの release は一つの構造テーマを持つ。
2. 前 release の unfinished acceptance を次 release の新機能で覆い隠さない。
3. self-host bootstrap と product canary を分ける。
4. runtime source、run version、installed copy を exact digest で pin する。
5. broad discovery は同じ SHA で一度集約してから修正する。
6. fix 後は known closure と regression challenge を必須にする。
7. budget 上限後は release を止め、quality bar を下げない。
8. scope 外 finding は follow-up に残す。
9. install parity と fresh-session capability を release gate にする。
10. retrospective lesson は local memory に candidate 登録し、user-gated promotion だけ commit する。

## success criteria across 0.5.x

品質:

- release-blocking finding の escape が減る。
- task-local Patch Review で adjacent regression が早く見つかる。
- final regression challenge が0件であることだけでなく、実行されたことを証明できる。
- unresolved finding が上限で失われない。

速度:

- 同じ SHA の full suite が原則1回になる。
- review collection 前の premature fix が0になる。
- Manager TUI approval message が0になる。
- requeue による cap reset が0になる。
- Manager handoff が10分以内に再開可能になる。

運用:

- runtime drift mutation が0になる。
- conflict graph を無視した parallel start が0になる。
- 同じ failure class の3回目が機械的に拒否される。
- batch close、requirement reconcile、progress projection が自動で一致する。

## 判断ポイント

各 version の開始前にユーザーへ次を相談する。

- version scope と非目標
- migration/rollback policy
- model/cost policy
- automatic remediation budget
- accepted-risk authority
- memory promotion と privacy policy
- external companion dependency

この roadmap は相談のたたき台であり、各 version の承認済み MISSION/PLAN を代替しない。
