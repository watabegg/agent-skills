# herdr-dev-loop 0.5.3 resume runbook

Status: proposed operator runbook

## 前提

この runbook は、ユーザーが 0.5.3 実装の再開を明示した後にだけ使う。現在の discussion draft を作成したこと自体は再開指示ではない。

旧 namespace `herdr-dev-loop-v0-5-3-run2` は直接 resume しない。旧 code candidate と evidence を fresh namespace へ移す。

## 0. 実行禁止事項

- 旧 T050/T051 pane を再生成して同じ attempt として扱わない。
- 旧 task を requeue して Patch Review history を消さない。
- old STATE を current 0.5.3 runtime でそのまま mutation しない。
- T050/T051 branch または worktree を削除しない。
- D008 の7 finding を第4回 T051 Patch Review へ付け替えない。
- R005/G053 以外の unrelated finding を recovery scope に足さない。
- production companion identity を test fixture で代用しない。
- ACK approval のために busy Codex pane へ Enter を送り続けない。

## 6. recovery branch

提案 branch 名:

```text

```

作成元は T051 candidate `3bbdb54` とする。ただし candidate が合格済みという意味ではない。T051 の7 finding と Patch Review 履歴を recovery manifest に open として登録する。旧 integration branch を reset、rename、force update しない。

T051 を起点にすることで、5,346行の候補差分を ACK seed の後から移植して上書きする危険を避ける。T050 は Manager が手作業で patch をコピーせず、source branch と exact tree を記録する Git transaction で取り込む。merge commit、squash import のどちらを使う場合も recovery manifest に方式と resulting tree を記録する。

bootstrap は ACK seed を作るためだけに使う。T050 import、history/metrics、guard、残り実装を続けない。

## 10. candidate import sequence

1. T051 baseline の source HEAD/tree、7 finding、resulting integration tree を再検証する。
2. PG01 で pre-mutation guard を統合する。
3. RI01 で T050 を import する。
4. `run_synthetic_e2e.py` の union conflict と T050 source identity finding を同じ task で解決する。
5. `git diff --check` と import-union verification を行う。
6. known finding ledger を再照合する。
7. SC01 以降を new base SHA で materializeする。

import 中は broad Reviewer/Gap を開始しない。コードを合格と認定する段階ではなく、既知候補を一つの integration surface にする段階だからである。

## 11. per-turn Manager checklist

各 Manager turn の最初に次を user-visible に報告する。

- exact runtime version/digest
- namespace/run ID
- phase と integration SHA
- active task
- weighted progress
- next gate
- user decision の有無

その後に次を実行する。

```text
version
dashboard
conductor --no-fail
manager next
manager brief
```

同じ turn で始める mutation は最大3件にする。

## 12. review and remediation

[Review convergence protocol](2026-07-19-review-convergence-protocol.md) を使う。

- 同じ SHA へ Reviewer と Gap を並行起動する。
- 全 lane が揃うまで修正しない。
- triage は一回。
- root cause batch で修正する。
- known closure と regression challenge を必須にする。
- release remediation は最大2回。
- 上限後は未解決 finding を保持して止まる。

## 13. release and install

final SHA で次を満たす。

- full test discovery
- exact-SHA synthetic matrix
- migration crash matrix
- selftest
- quick validation
- independent manual-final
- 57 acceptance conditions
- release dependency identity
- Codex installed copy parity
- Claude installed copy parity
- fresh-session capability handshake

install は source skill を置き換える形で行い、source digest と installed digest を比較する。test fixture の companion を production available と記録しない。

## 14. old run terminalization

fresh run が recovery manifest を受理し、候補 import が再現できた後にだけ old run を terminalize する。

推奨 outcome:

- status: `handoff` または `superseded`
- successor namespace
- successor run ID
- recovery manifest digest
- preserved candidate refs
- reason: runtime drift and missing panes; evidence salvaged, role state not resumed

old worktree と branch は release 完了まで削除しない。release 後も branch ref は少なくとも retrospective retention 期間中残す。

## emergency stop

次の場合は即座に pause する。

- old run の artifact digest が変わった。
- recovery branch 以外へ product commit しようとしている。
- current runtime digest が pin と違う。
- active conflict を持つ2 task が start されようとしている。
- task contract を start 後に変える必要がある。
- 同じ TUI/cleanup/runtime failure が2回発生した。
- scope 外 finding が fix task へ入った。
- review budget を requeue で回避しようとしている。
- user の回答が必要なのに推測で進めようとしている。

pause 時は候補、worktree、review history、broker event を削除しない。
