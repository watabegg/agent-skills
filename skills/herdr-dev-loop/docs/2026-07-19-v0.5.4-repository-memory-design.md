# herdr-dev-loop 0.5.4 repository memory design

Status: design proposal

## 目的

同じ repository で HLoop を繰り返し使うとき、run や Manager session を跨いで次を保持する。

- repository 固有の domain knowledge
- 過去に起きた operational failure
- failure の trigger と検証済み recovery
- skill 自身の既知の弱点と version 条件
- task 分解時に守るべき invariant
- 反証され、今は使ってはいけない古い教訓

memory は issue tracker ではない。現在の product finding、未実装 feature、一般的な TODO は既存の finding inventory、follow-up、PLAN で管理する。

## 基本原則

### scope を増やさない

memory は advisory evidence である。優先順位は常に次とする。

1. current user instruction
2. MISSION と accepted decisions
3. PLAN、requirements、release scope
4. active task contract
5. verified memory
6. candidate memory

memory を根拠に scope 外 task を自動作成しない。current contract と矛盾する memory は適用せず、stale candidate として提示する。

### fingerprint に依存しない

旧 run では112 finding occurrence 中 exact fingerprint の重複は3組だけだった。同じ失敗は同じ文字列や path ではなく、cleanup、identity、durability などの failure class として再発した。

memory の近似照合は fingerprint ではなく、failure class、violated invariant、affected surface、trigger shape を使う。自動統合はせず、Manager に候補を提示する。

### evidence と反証を残す

成功した対処だけでなく、誤っていた仮説と反証理由も残す。削除すると、次の Manager が同じ誤推論をやり直すためである。

### local-first、user-gated promotion

観測と運用履歴は local-only store に置く。複数 repository や配布先で有益な verified lesson だけ、ユーザー承認後に repository の docs へ昇格できる。

## repository identity

### primary ID

Git common directory に random UUID を一つ保存する。

```text
$(git rev-parse --git-common-dir)/herdr-dev-loop/repository-id
```

全 worktree は同じ Git common directory を共有するため、同じ repository memory を参照できる。file 内容は UUID と schema version だけにする。

### clone behavior

別 clone は別 UUID になる。remote URL が同じだけで自動統合しない。fork、mirror、credential 付き URL を誤って同じ repository と扱う危険があるためである。

alias candidate は次から生成できる。

- normalized remote host/path digest
- initial root commit
- repository root basename
- user-supplied label

alias merge は Manager が提案し、ユーザーが明示確認した場合だけ行う。merge event は append-only ledger に残す。

## storage root

既定:

```text
${XDG_STATE_HOME:-~/.local/state}/herdr-dev-loop/repositories/<repository-uuid>/
```

構成:

```text
<repository-uuid>/
├── repository.json
├── memory.sqlite3
├── lock
├── projections/
│   ├── manager-brief.md
│   ├── manager-brief.json
│   ├── worker-guardrails.json
│   └── review-challenges.json
├── exports/
│   └── verified-lessons.jsonl
└── quarantine/
```

repository root の `.ai/` や skill directory の中を正本にしない。worktree cleanup、directory rename、run archive から独立させるためである。

`repository.json` は次を持つ。

- repository UUID
- created at
- known root aliases
- Git common directory digest
- current schema version
- privacy policy version
- last opened runtime version
- alias merge history refs

## SQLite model

SQLite は WAL mode、single Manager writer とする。role は直接書かず、authenticated report で candidate observation を提案する。

### `incident_events`

append-only event log。

- event_id
- repository_uuid
- observed_at
- run_id、namespace、skill_version
- source role/attempt/artifact digest
- event_type
- failure_class
- symptom summary
- trigger shape
- affected surface
- violated invariant
- evidence digest refs
- privacy classification
- supersedes_event_id

### `lessons`

current projection。

- lesson_id
- canonical key
- title
- status
- scope: repository / skill / provider / Herdr
- failure class
- invariant
- applicability expression
- recovery procedure
- verification procedure
- first seen / last confirmed
- introduced version / fixed version
- confidence
- invalidation condition
- promotion status
- current event head

### `evidence_refs`

- evidence_id
- artifact class
- relative or opaque reference
- content digest
- source SHA
- observed result
- verified by
- recorded at
- availability state

raw log や user input 本文を database へ複製せず、digest と safe summary だけを保存する。

### `repository_aliases`

- alias ID/type/value digest
- repository UUID
- status: proposed / accepted / rejected / revoked
- authority ref
- created/resolved at

### `projection_history`

- projection ID
- target role/task
- source lesson IDs and versions
- token budget
- generated digest
- created at
- stale at/reason

## lesson state machine

```text
candidate -> verified -> stale -> verified
    |           |          |
    v           v          v
 refuted     resolved    refuted
```

### candidate

一回の観測または未検証の仮説。Manager brief の main guardrail には入れない。関連 task の「確認候補」として小さく提示できる。

### verified

再現 test、複数 run の観測、または単一 run の十分な定量証拠がある。applicability 条件と recovery test が必要である。

### refuted

仮説が誤りだった。反証 evidence と reason を残し、同じ提案を再作成したときに警告する。

### stale

runtime version、affected path、dependency、invalidation condition が変わった。使用前に再検証が必要である。

### resolved

原因が product/skill change で修正され、regression evidence がある。history として残し、fixed version より古い run だけへ適用する。

## canonical key と near-duplicate

canonical key の入力:

```text
scope
failure_class
violated_invariant
normalized_affected_surface_prefix
normalized_trigger_shape
```

semantic fingerprint や finding title は evidence として持つが key の唯一の入力にしない。

新 event が入ると、同じ canonical key と近い lesson を候補表示する。

- exact canonical key: append proposal
- same class/invariant, different surface: sibling proposal
- same symptom, different invariant: do not merge
- opposite outcome: contradiction proposal

Manager が `append`、`new sibling`、`contradict`、`ignore` を選ぶ。自動 merge はしない。

## Manager projection

### token budget

default 1,200 tokens、hard max 2,000 tokens を提案する。全 memory を prompt へ入れない。

優先順位:

1. current mutation を禁止する verified guardrail
2. active task surface に適用される verified lesson
3. open circuit と required recovery
4. current runtime に stale かもしれない lesson
5. candidate hypothesis

各項目は次だけを出す。

- lesson ID
- applicability
- one-line risk
- required action
- verification command/ref
- status/version

### Worker projection

task contract の write surface と preserved invariant に合う verified lesson だけを最大600 tokens で渡す。Worker は lesson を新要件として扱わず、self-review と regression check の補助に使う。

### Reviewer projection

既知 finding を答えとして教えすぎない。次を分ける。

- closure lane: exact source finding と verified recurrence lesson
- regression challenge: failure class のみ、具体的 path/answer は最小限

fresh-eyes を失わないためである。

## write path

### observe

Manager は task failure、conductor warning、review finding、user correction、retrospective から observation を登録する。

```text
hloop memory observe \
  --failure-class transport.tui-submit-unknown \
  --surface provider/codex-tui \
  --invariant "Manager message is submitted exactly once" \
  --evidence <artifact-ref> \
  --summary <safe-summary>
```

### verify

```text
hloop memory verify <lesson-id> \
  --evidence <regression-ref> \
  --applicable 'skill_version < 0.5.4' \
  --recovery <procedure-ref>
```

### invalidate

runtime upgrade、file/module removal、test failure、contradictory observation が invalidation candidate を作る。自動で削除せず `stale` へ移す。

### promote

verified lesson を committed docs へ昇格する場合、diff preview と privacy review を提示し、ユーザー承認を要求する。

```text
hloop memory promote <lesson-id> --target skills/herdr-dev-loop/docs/operational-lessons.md --dry-run
```

## privacy

### 保存禁止

- raw user input
- token、API key、credential
- authentication cookie
- home directory の秘密 path
- pane/session transcript 全文
- private URL query
- personal data

### 保存可能

- redacted summary
- content digest
- relative artifact ref
- event timestamp
- provider/model class
- safe command name
- error class

projection 前に allow-list based serializer を使う。free-form fields は既存 redaction を通し、credential-like pattern が残れば quarantine する。

## concurrency and ownership

- Manager process だけが SQLite writer lease を取得できる。
- Worker/Reviewer/Gap/Advisor は observation event を broker へ送るだけである。
- worktree から direct DB path を書けない。
- WAL と busy timeout を使うが、競合時に last-write-wins をしない。
- lesson state transition は expected current event head の compare-and-swap を要求する。
- repository alias merge は global lock と user authority ref を要求する。

| busy Codex TUI への Manager message は unknown/undelivered になりやすい | `transport.tui-submit-unknown` | 旧 run JOURNAL と STATE |
| ACK approval notification を pane input に依存させない | `transport.approval-pane-cycle` | 133 unknown、61 undelivered の event count |
| requeue が review history と semantic barrier を消す | `review.budget-reset-attempt` | T010/T041 round history と code path |

各 lesson は source artifact digest、version applicability、reproduction/verification を追加してから verified にする。

## migration and retention

- schema migration は prepared/committed marker を使う。
- unknown partial bytes は fail-closed にする。
- backup は database と repository metadata の consistent snapshot にする。
- incident event は append-only で保持する。
- large evidence body は参照先の retention に従い、database には availability state を残す。
- resolved/refuted lesson は削除せず、projection から外す。
- user は repository memory 全体を export、inspect、delete できる。

## CLI proposal

```text
hloop memory init
hloop memory status
hloop memory observe
hloop memory list
hloop memory show <lesson-id>
hloop memory verify <lesson-id>
hloop memory refute <lesson-id>
hloop memory stale <lesson-id>
hloop memory resolve <lesson-id>
hloop memory project --role manager|worker|reviewer --task <id>
hloop memory aliases
hloop memory alias-merge --dry-run
hloop memory promote --dry-run
hloop memory lint
hloop memory export
```

`loop init` と `manager brief` は memory がなくても動く。memory failure で core loop を止めるのは、current circuit が critical guardrail を要求している場合だけにする。

## 受入条件

1. 同じ repository の全 worktree が同じ UUID と store を使う。
2. 別 clone は明示 merge なしに同じ store を使わない。
3. Manager 以外の role は database を直接 mutation できない。
4. event history は append-only で、lesson projection を再構成できる。
5. candidate、verified、refuted、stale、resolved の transition が監査可能である。
6. fingerprint が違う同じ failure class を near-duplicate 候補にできる。
7. near-duplicate を自動 merge しない。
8. Manager projection は token budget を超えない。
9. Worker projection は active task contract の scope を増やさない。
10. current user/MISSION/PLAN/task contract と矛盾する lesson を適用しない。
11. raw user input と credential が database/projection/export に入らない。
12. runtime/version/invalidation condition の変化で lesson を stale にできる。
13. refuted lesson が同じ仮説の再登録時に警告される。
14. promotion は dry-run diff と user approval を要求する。
15. memory が unavailable でも safe default で loop preflight を行える。
16. old run の verified lesson を fresh run の Manager brief へ選択投影できる。

## 非目標

- repository の一般的な knowledge base を作らない。
- product issue tracker や backlog を置き換えない。
- LLM が自由文から自動で verified lesson を作らない。
- remote URL だけで clone memory を自動統合しない。
- 全 transcript を保存しない。
- memory から自動で code fix task を作らない。
- 0.5.4 で中央 `hloop` の全面分割まで同時に行わない。

## rollout

1. 0.5.4-A: repository UUID、SQLite schema、observe/list/show、privacy serializer
2. 0.5.4-B: state machine、evidence validation、near-duplicate proposal
3. 0.5.4-C: Manager/Worker/Reviewer projection と token budget
4. 0.5.4-D: handoff capsule、circuit integration、promotion flow
5. canary: この repository で旧 0.5.3 lesson を import し、一つの bounded task を fresh Manager が引き継ぐ
6. release: migration、backup/restore、privacy audit、Codex/Claude install parity

0.5.4 の canary 成功条件は、同じ session を長く保つことではない。新 Manager が旧 thread を読まず、brief と verified memory から scope 内の next action と stop condition を正しく再現できることである。
