# tex-course-report

## 概要と適用範囲
本スキル（`skills/tex-course-report/`）は、大学の数値計算や技術系演習レポートを既存の LaTeX テンプレート、計算根拠、読みやすい自然な日本語で作成または改訂する。一般的なビジネス文書や文芸的エッセイは対象外とし、固定の最適化定式や固定の章数に縛られず課題要件と利用者の好みに合わせる。特定モデルや高額なエージェント構成、固定の見出しや規定長、冗長なレビュー段階を前提とせず、一般的な能力のエージェントで動作する。文面より事実を先行させ、限定的な確認を行うことで成果物の信頼性を担保する。なお、参照資料やスクリプトのパスは、作業ディレクトリに依存せずスキルディレクトリ基準で解決する。

## 成果物と作業境界
- **成果物**: 利用者の確認用にローカルの TeX レポートと PDF を作成する。計算を伴う課題では、実験再現に必要なコードとデータも準備する。
- **指示の遵守とメタデータ**: 実際の課題、既存テンプレート、ビルド手順、AGENTS 指示、利用者指示に従う。氏名、学籍番号、教員名、日付を捏造せず、確認済みテンプレートメタデータのみを引き継ぎ、実質的な曖昧さは明示する。
- **作業範囲**: レポートのローカル準備のみを担当し、個別の明示的な指示がない限り LMS 提出、外部送信、コミットやプッシュは行わない。
- **過去資料の扱い**: 過去レポートは参考資料であり現在の課題の正解ではない。明示的な指示がない限り上書き、再整理、退避、年度削除を行わない。整理を指示された場合はパスを対応付けて内容を保持し、年度や科目番号を固定値で埋め込まない。
- **証跡の分離**: 生の課題メタデータ、URL、ダウンロード証跡、詳細な実行・QA ログは追跡用資料とし、本文に含めず非公開証跡は公開リポジトリから除外する。

## 根拠データの準備
1. **課題と環境の確認**: 課題文、添付資料、テンプレート、ビルドコマンドを確認する。認証が必要な URL は利用可能な認証・閲覧スキルを読み取り専用で使うかローカル資料を参照し、遮断時にアクセス成功を前提としたり推測で進めたりしない。
2. **要件抽出**: 提出物、数式、境界、刻み幅、初期値、呼び出し回数の定義、図表、文献等の指定を整理する。必須条件、利用者の選択、自身の仮定を区別し、未指定の2次元関数を任意に選ぶ場合は明記して出題者指定と偽らない。
3. **計算の先行実施**: 執筆前に再現実験を行い、パラメータと目的関数呼び出し回数を含む表データを保存する。適切な独立計算や既知の極値等で検証し、自己出力を唯一の正解基準としない。課題要件と根拠を対応付け、強い主張にはデータや数式導出を伴わせる。
4. **データの管理**: 生の数値根拠と丸め表示用の表を分離し、表の行数やカウント数と本文の記述を一致させる。実験変更時は図、表、本文を一貫して更新する。根拠データの整理とパケット作成時は [material-packet.md](references/material-packet.md) を参照する。

## 執筆手順
文体は [writing-profile.md](references/writing-profile.md) を参照して既定の調子を適用し、講義指定形式や利用者の希望を最優先とする。先行下書きは作らず、事実、決定事項、実データ、希望言語をパケットにまとめて執筆する。

1. **章の生成**: `agy-writer` が利用可能な場合は読み込み、章執筆・編集と意味レビューを使用する。パケットに要求言語とレポート様式を渡し、対応時は `--profile` にスキルディレクトリ基準のパス（`references/writing-profile.md`）を指定する。固定章数は求めず、内容がグループ化された長い文書でのみ `--plan` を使う。
   ```bash
   agent-write-ja chapters --packet <private-packet.md> --out <private-draft.md>
   ```
2. **双方向照合と局所修正**: `needs_review` は暫定とし、同一エージェント・会話内で生成文全体と元の要件・根拠を双方向に照合し、利用者の文体指定、プロファイル、不要な注記を省く情報選別を満たしているかも確認する。文面の言葉遣いは Gemini が担い、事実の確定は主担当が担う。実質的な不一致は、一意に特定できる正確な該当箇所、根拠や指示、問題点を `agy-writer` のピンポイント修正に送り、修正後の文脈を再確認する。Gemini の文章を手動で直接書き直したり、修正ごとに新しいレビュー役を立てたりしない。
3. **不在時の対応**: `agy-writer` が真に存在しない場合は上位指示を確認し、禁止されていなければ新たな承認を求めずに同一プロファイルと事実照合のもとで直接執筆する。必須指定されたライターの CLI 失敗時は不在とみなして勝手に迂回せず原因を調査するが、任意ライターの不在だけで作業全体を中断しない。
4. **テンプレート反映**: テンプレート構造を機械的に維持・調整して本文や図表を配置し、Markdown、数式、箇条書きの変換で意味を暗黙に変えない。出所を示すためだけに課題ファイル名や URL を表示用の参考文献欄へ転記することは避ける。

## 最終検証と報告
1. **ビルドと外観検証**: プロジェクト指定のコマンドでビルドし、未解決参照（`?` や `??`）、文字のはみ出し、エラーを最終パスで確認する。PDF は利用可能な PDF スキルを用い、意味のある最後の変更の後に全ページを描画検査し、指定の用紙サイズやページ条件も実 PDF で確認する。テキスト抽出のみでレイアウトを検証しない。
2. **数値と要件の再点検**: 数値や表と本文の対応、および要件網羅性を再点検する。禁止メタデータや注記の検索は補助とし、コードや数式の丸括弧に一律の正規表現を適用しない。文言修正のみのときは元データや成果物のハッシュを保持し、入力やコードの変更、または疑念がある場合のみ実験を再実行する。
3. **報告**: 成果物パス、代表的な編集、確認内容を簡潔に報告し、該当時は未提出であることを明記する。ビルドコマンド、内部検証回数、下書きや自己修正の注記は本文に含めず、再現手順の詳細は必要に応じて別 README に記載する。
