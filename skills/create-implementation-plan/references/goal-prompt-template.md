- 完了条件: todo 全行消し込み + 全 Hard Gate PASS + 完了報告に「計画書からの逸脱」セクション必須。

## 正本参照ブロック

- 計画書: `[絶対パス]`
- 進捗台帳: `[絶対パス]`
- 許可パスリスト: [`path/**` を列挙。実装中に `git diff --name-only` で照合し、リスト外の変更があれば停止して報告する。計画成果物（計画書、todo.md、goal prompt、図、QA 証跡）と実装開始前から dirty だったファイルは照合対象から除く]
- コミット状態: [計画書と todo.md を含む commit の SHA を記す（このファイル自体はその commit に含まれなくてよい）。未コミットのファイルは別 checkout やクラウド環境の実装エージェントに届かない]

## 事前回答（preflight）

ユーザーが計画レビュー時に実際に回答した値だけを記入する。未回答の項目は「未回答」と記入し、codex-impl が kickoff で質問する。planner の推測で埋めない。

- gap-check 回数: [0 / 1 / 2 / 未回答]
- レビューループ上限: [skip / 3 / 5 / 10 / 未回答]
- QA 環境: [local / staging / PR preview / 未回答]

## 再開手順（別セッション・コンテキスト圧縮後）

1. todo.md を全文読み、ヘッダの「アクティブタスク」から再開位置を特定する。
2. 計画書の「Hard Gate」「Out of scope」と現在 Step の本文を再読する。
3. 現在の Step を1行で宣言してから作業を再開する。
4. 鮮度チェック: 次のいずれかに該当する場合、着手前に全 Step / Todo を keep / redesign / close の3値で再検証する。
   - 計画検証日時から24時間超が経過している。
   - base branch が計画時点の sha から進んでいる（計画成果物のみのコミットと、この実装 run 自身のコミットは除く）。
   再検証の結果、redesign / close が3割を超えるか、重大な前提（schema、API 契約、認証、依存バージョン）が1つでも変わっていたら、件数によらず計画を改訂して再提示する。
